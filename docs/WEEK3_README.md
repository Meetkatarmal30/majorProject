## 3. t-SNE Visualization Utility

### **Purpose**
Reduces high-dimensional embeddings (e.g., of size 128 or 256 dimensions) to a 2D space using t-Distributed Stochastic Neighbor Embedding (t-SNE). It plots them to inspect class separability.

### **Inputs**
* `embeddings`: NumPy array of shape `(N, D)` representing the features.
* `labels`: Optional array of strings/integers of shape `(N,)` to color-code points.
* `save_path`: Path to save the PNG image.
* `perplexity` / `learning_rate` / `random_state`: Hyperparameters for t-SNE.

### **Outputs**
* Returns a NumPy array of shape `(N, 2)` containing 2D coordinates.
* Saves a publication-quality scatter plot under `outputs/`.

### **Example Usage**
```python
from pathlib import Path
import numpy as np
from evaluation.tsne_visualization import generate_tsne_plot

# Load S1 features
embeddings = np.load("embeddings.npy")
labels = ["urban", "forest", "water", ...]

generate_tsne_plot(
    embeddings=embeddings,
    labels=labels,
    save_path=Path("outputs/tsne_plot.png"),
    title="S1 Latent Space t-SNE Plot"
)
```

## 4. Timing Utility

### **Purpose**
Measures pipeline execution times, including model loading, single-image encoder latency, batch-image encoder latency, and database query search speed.

### **Benchmark Metrics**
* **Model Load Time**: Duration to transfer the model to the target hardware device (CPU/GPU).
* **Single Inference Latency**: Average time (ms) to encode a single image.
* **Batch Inference Latency**: Average time (ms) to process a full batch.
* **Throughput**: Number of images processed per second (`samples/sec`).
* **Average Retrieval Latency**: Mean time (ms) to run a k-NN similarity lookup in the database per query.

### **Example Usage**
```python
from evaluation.timing import run_complete_benchmark

results = run_complete_benchmark(
    model=trained_pytorch_model,
    dataloader=test_dataloader,
    device="cuda",
    retrieval_fn=search_routine_callback, # Callable k-NN matching function
    query_embeddings=query_vecs,
    database_embeddings=db_vecs,
    save_path=Path("outputs/timing_results.json")
)
```

## 7. Performance Notes

* **GPU Execution (CUDA)**: Pushes `torch.cuda.synchronize()` before and after time records to wait for asynchronous GPU execution, providing exact GPU latencies.
* **CPU Fallback**: Automatically disables GPU synchronization if CUDA is unavailable, returning CPU-only performance metrics.
* **Warm-up Loop**: Performs a single mock execution run prior to benchmarking. This forces CUDA compilation graphs and CPU cache loading, isolating the measurement of standard steady-state runtimes.

## 8. Troubleshooting

| Error / Issue | Cause | Solution |
| :--- | :--- | :--- |
| `TypeError: unexpected argument 'n_iter'` | Old/New scikit-learn API changes. | Handled automatically. The module dynamically inspects signatures to map to `max_iter` or `n_iter`. |
| `ValueError: perplexity must be < n_samples` | Sample size too small. | Handled automatically. The module clips perplexity dynamically based on input size. |
| CPU Throughput is Low | `num_workers` set to 0. | Set `num_workers = 4` in `DataLoader` to parallelize disk operations. |
| `CUDA out of memory` | Batch size is too large for GPU. | Reduce `batch_size` in the `create_dataloaders` call. |

## 9. Future Integration

* **Model Agnostic**: Utilities accept any PyTorch model (`torch.nn.Module`) and NumPy matrix, making them fully independent of the eventual encoder architecture.
* **FAISS Support**: The retrieval timing callback (`retrieval_fn`) is structured to accept any search function, including FAISS indexes or customized KD-Trees.
